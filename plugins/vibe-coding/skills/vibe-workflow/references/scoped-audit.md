# Scoped Audit

## Scope

Audit the named behavior when no specialized recipe applies. Establish the target, intended contract, relevant version/capability and evidence sources from the request and repository.

## Procedure

Trace input through its defining code, schema or configuration to direct consumers and relevant failure/recovery states. Compare expected and observed behavior using a concrete trigger. Use version-matched official documentation only when the repository does not establish an external guarantee.

## Result

Return supported defects with source evidence, impact, one correction and an observable acceptance criterion. If the expected behavior depends on an unresolved decision, identify it; continue independent inspection rather than requiring a prewritten audit input package.

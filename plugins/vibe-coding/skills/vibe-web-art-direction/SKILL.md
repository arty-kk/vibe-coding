# Web art direction & experience system

Apply [the working contract](../../references/workflow.md) once. Use the actual offer and page narrative from the task or [Web Strategy](../vibe-web-strategy/SKILL.md). Translate an ordinary request such as “make it feel premium and alive” into observable choices; the user need not supply design terminology.

| Missing decision | Current prompt |
|---|---|
| Useful references, real assets, appropriate techniques and source constraints | [Web Reference Research](references/web-reference-research.md) |
| A distinctive concept and section-by-section composition | [Web Art Direction](references/web-art-direction.md) |
| A coherent logo family, favicon, browser/app icons and sharing assets | [Web Brand Assets](references/web-brand-assets.md) |
| Exact type, color, grid, icon, component and material rules | [Web Visual System](references/web-visual-system.md) |
| Compile chosen parameters into a local token/material review kit | [Web Design Kit](references/web-design-kit.md) |
| Functional modules, transitions, animation and responsive state changes | [Web Interaction Storyboard](references/web-interaction-storyboard.md) |

For a complete proposal, carry references → art direction → brand assets → visual system → interaction storyboard into [Web Experience Brief](../vibe-landing/references/web-experience-brief.md). Verify and reuse an accepted identity when one exists. Load the next prompt when its decisions become necessary; a narrow component change does not reopen the whole design.

Make the offer recognizable through composition, useful imagery and a small number of characteristic gestures that recur coherently. Vary sections by what their content needs while retaining a common type, grid, color and interaction logic. A glass surface, procedural field or 3D scene needs a role, parameters, reading conditions and a feasible fallback. Treat a fashionable technique as a choice to justify, not as a definition of quality.

Carry actual assets and their provenance, proposed assets still to obtain, tokens, section compositions, component states and unresolved rendering questions into the build brief. A moodboard or list of adjectives alone is not implementation-ready. The host's tools and permissions govern research and asset production; do not assume a particular image, design, browser or rendering service exists.

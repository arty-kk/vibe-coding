# Homepages & landing experiences

Apply [the working contract](../../references/workflow.md) once. Identify the requested result and current stage. A broad request such as “make a great website for my studio” needs the offer and page concept derived from available facts; it does not require the user to know design terms or workflow names.

For a visual request, read the intended impression, the focal element and the requested degree of change together. Treat “soft”, “barely visible” and “without overdoing it” as limits on the effect. A request to adjust one relationship such as the boundary between a panel and its background starts with that existing composition and the focused redesign recipe.

A full proposal carries offer → page architecture → [copy](../vibe-content/references/web-page-copy.md) → [references/art direction/brand/visual system/storyboard](../vibe-web-art-direction/SKILL.md) → project architecture → implementation brief. Reuse established inputs and load only the current prompt. A proposal ends before implementation unless a build was requested. Ordinary creative decisions should become a coherent proposal, not a succession of approval questions.

Choose the project mode from the request and actual files: **new** establishes the missing foundations and builds; **finish** reconciles a partial result with the intended brief and completes its gaps; **redesign** changes the authorized visual/content/interaction direction while preserving required data, routes and working effects. A requested redesign may replace unsuitable compositions, but does not silently rewrite business rules, migrate the stack or deploy. Carry this mode and the preserved boundaries through the checks.

For a new build or authorized improvement, preserve the original requirements and comparison base through visual, navigation/state, interaction/motion, search/performance and final acceptance checks, then [Patch Checking](../vibe-review/references/patch-checking.md). Select checks by their stated applicability for a bounded change; a complete new page needs coverage across all relevant areas. Return a failed case to its owner and recheck after correction. Repeat Patch Checking until an unchanged complete pass or a concrete gate.

Carry the requirement ledger, page/route, exact content, assets and their availability, tokens/components, state contracts, architecture, patch and actual evidence. A known missing asset, useful destination, working integration or required check remains open; a polished placeholder or a source-only assertion cannot close it. Distinguish proposed, built, tested and published results.

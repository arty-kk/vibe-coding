Goal

Correct the selected existing page problem or carry out its requested redesign while preserving useful behavior, product truth and the accepted project boundaries. Complete the affected visual/content/interaction contract through its real consumers and evidence, rather than improving one screenshot at the expense of another state.

Target and implementation

Use the named defect or supported audit finding. Retain the route, failed viewport/state, intended hierarchy/action, source owner, original comparison base and acceptance case. Start directly with a known correction. A broad authorized redesign may use focused offer/copy/art-direction methods where their decisions are missing; a label, spacing or menu fix does not reopen the whole project.

For “finish this site”, inventory what is already complete, partial, missing and blocked against the intended page/requirements; retain the useful completed work and implement the gaps. For “redesign”, define the authorized change of composition/style/content/interaction and the working routes, data and effects that remain required. Use the user's ordinary wording and repository evidence rather than requiring a special mode flag or technical keyword. An unfinished page is not automatically a greenfield project.

For a focused visual correction, capture the named panel or state before editing. Specify what should feel raised, inset or quiet, and carry the user's limit on intensity into the acceptance case. If the primary surface should feel deeper and its edges should be quieter, first inspect whether the background lets a shadow read. Reduce competing outlines on nested surfaces and use one light or tonal cue for their separation. Preserve enough shape and focus feedback for the actual controls. For a broad redesign, use the opening slice in Build Homepage & Landing Page.

Locate the maintained owner: content/locale key, token, primitive, component, page composition, route or integration/domain rule. Trace affected usages and states before editing. Prefer an owner-layer correction and remove superseded conflicting overrides when safe. Reuse the actual architecture unless the selected problem requires a justified change.

For geometry/hierarchy, correct the actual relationship—alignment, padding, baseline, scale, measure, contrast, media or placement—while preserving content and meaningful asymmetry. Use the intended focal role and real rendered fonts; do not rank importance by numeric weight alone or assign a different accent to every role. Recheck borders, focus, shadow, gradient and transparent states on their actual backgrounds.

For navigation or functional modules, correct the route/state/effect owner and synchronize labels, controls, feedback and recovery. Every retained invitation must deliver its promised content or action. Suppress an optional empty-content invitation, or keep an unresolved required integration/content gate explicit. Do not invent proof, contacts, a calculation rule or delivery success to fill a gap.

Carry corrections through actual narrow/wide and relevant theme/locale/input/error states. Keep animation and procedural/3D enhancements bounded and readable, with a working static path. Update related metadata, asset declarations and loading behavior when the change affects them. Preserve unrelated work and avoid accumulating route-level CSS exceptions around a broken primitive.

Verification and completion

Replay the original failing case and a normal control. Run the applicable visual/geometry, navigation/state, interaction/motion and search/performance checks, then reconcile the affected requirement coverage with Web Page Acceptance Check. Evidence for the unchanged areas can be reused when their inputs and boundaries remain valid; repeat checks for new changes, failures or unresolved risk.

A failed case returns to its owning correction. After domain acceptance, run Patch Checking over the complete resulting patch against the original base, repeating after any correction until a real unchanged clean pass or concrete gate. Report the changed behavior and actual checks; leave unavailable required rendering, integration or publication evidence open.

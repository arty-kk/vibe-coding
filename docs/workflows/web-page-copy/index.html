Goal

Write a complete, professional text deck for the actual homepage or landing page and its selected interaction states. Give visitors clear, useful language and give the builder real strings to design around. Copy must fit the offer, audience, language and action contract; headings labelled “benefits” and generic example sentences are not a finished deck.

Inputs and voice

Use the current offer, section ledger, proof, brand constraints and selected modules. Recover existing domain vocabulary from maintained product/service documentation and actual approved content. Identify the site's audience, locale, level of formality, important technical terms and naming conventions. Preserve accepted terminology; verify an unfamiliar term when it changes the meaning. Professional language is accurate and natural for this audience, not automatically formal or full of industry jargon.

Distinguish product facts, proposed wording and unresolved policy/data. Keep prices, qualifications, availability, timelines, outcomes, customer attribution and contact details grounded in supplied or verified sources. A missing fact gets a specific internal content requirement or a truthful simpler formulation. It does not become a fabricated testimonial, generic superlative or unapproved promise.

Write the page

  1. Establish a short glossary: canonical offering and audience names, important features/services, action verbs, quantities/units and words whose translation or register matters. Record consequential exclusions, such as “consultation request” versus “reserved appointment”. Keep internal guidance outside visible strings.
  2. Write the actual opening proposition, supporting explanation, primary/secondary actions and useful reassurance. Make the offer understandable on its first reading. The focal visual and heading should complement each other; avoid a headline whose meaning depends entirely on an unseen image.
  3. Write each selected section in its intended role. Benefits should connect a real capability to the visitor's outcome; process text should explain real responsibilities and sequence; project/case text should expose evidence; comparisons should use comparable criteria. Remove repeated promises that only add page length. A section title can be expressive while its body remains concrete.
  4. Write navigation, footer groups, link labels, media captions and applicable accessibility text. Navigation names must predict destinations. Add a caption when it identifies or explains useful content, not under every decorative shape. Alternative text describes the purpose of the actual selected image; an unavailable image needs a content requirement until inspected.
  5. Write the selected modules' full text state model. Include field labels and necessary hints, required/optional meaning, empty/default state, selected options, calculation assumptions/results, loading/pending, validation, accepted result, failure/unconfirmed result and recovery. Use only states the component can actually reach. A success message requires the corresponding acknowledged effect; a timeout can leave delivery uncertain.

Microcopy and linguistic pass

Give a button a short verb or verb-plus-object that predicts its action. Put conditions, reassurance and instructions beside the control rather than inside a sentence-length label. Keep the same action name consistent across entry points. Distinguish ordinary navigation, opening a dialog, downloading, submitting and committing to a purchase or booking. Repeated “Learn more” links need enough context to identify their distinct destinations. Confirm that the promised content or action actually exists: an unpublished-content message is not a portfolio. Keep an optional invitation out of the published deck until its destination is useful; a missing required conversion path remains a release gate.

Read the finished strings as complete sentences in their actual locale. Check agreement, case, prepositions, number, tense, punctuation and domain usage. In Russian, verify declined nouns/adjectives, gender agreement and count forms; in Spanish, keep address/register consistent; in Chinese, check natural wording and punctuation instead of preserving English word order. Preserve variable boundaries, currency, dates, units and localization keys. For dynamic quantities, use the project's locale-aware formatting/pluralization and test representative forms such as 0, 1, 2, 5, 11 and 21 where they matter. Do not concatenate fragments that require different grammatical forms.

Remove copy that talks about the generation or layout process: instructions to a builder, “this block explains”, implementation notes, filler captions and self-evaluation do not belong in a visitor-facing sentence. Keep actual product vocabulary when the product itself concerns design or AI. Do not remove meaningful safety, price, privacy or service limitations merely to make the page sound smoother.

Check label lengths using the actual words and proposed component width. Shorten text without changing its commitment; reflow or adapt the component when the meaning needs more space. Do not enforce one character limit across all languages or hide essential words with truncation. Placeholder text does not replace a persistent field label.

Result and handoff

Return a copy deck keyed by section/component and state, with exact visible strings, the glossary and any relevant variable/plural forms. Keep factual sources, rationale and missing-content notes in separate internal fields so they cannot accidentally become interface copy. Include title/description drafts consistent with the page; engine eligibility and technical metadata are checked in the search-visibility workflow.

Cross-check the deck against the section and module ledger: every visible action/state has text, promises match destinations, and no required content has silently disappeared. Pass real strings and constraints into Web Reference Research, art direction and implementation. Revisit affected strings if a later interaction decision changes their meaning. A planning request stops with this deck; editing deployed content requires the corresponding implementation scope.

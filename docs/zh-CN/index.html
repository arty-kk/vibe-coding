Vibe Coding 是一款开源插件，包含 46 项技能和 241 个工作流，用于梳理仓库、代码审查、调试、实现和验证。给助手一项具体任务，也给它一套解决问题的方法。

按你的任务选择工作流

每项技能会选择对应的具体指令。助手沿着相关代码找到契约的定义位置，并检查受影响的行为。详细工作流按需加载。

检查

请求审计或审查，获得证据、影响说明和明确的下一步。产品代码保持不变。

实现

请求修复或改进，即授权进行相关修改，包括受影响的调用方和契约。

验证

检查指定行为，区分通过、失败和无法验证的情况。局部检查不能证明整个项目都没有问题。

从真实的工程任务开始

梳理仓库 ↗

在修改陌生代码前，追踪 API、数据归属和运行流程。

审查变更 ↗

检查完整变更及其直接依赖，找出可处理的具体缺陷。

修复故障 ↗

追踪可复现错误的源头，修复原因并执行有意义的检查。

检查发布 ↗

对照发布条件核实检查结果，明确尚未满足的要求。

安装插件

两个助手使用相同的 46 项技能。请选择你用于仓库开发的助手。

Codex

从 OpenAI 插件目录安装 Vibe Coding，然后开始一个新任务。

在 Codex 目录中打开 ↗

$vibe Map this repository and explain its main contracts.

Claude Code

添加这个公开的 GitHub 插件市场，然后在 Claude Code 中安装插件：

claude plugin marketplace add arty-kk/vibe-coding
claude plugin install vibe-coding@vibe-coding

开始新的 Claude Code 会话，并使用带插件命名空间的命令调用技能：

/vibe-coding:vibe Map this repository and explain its main contracts.

关于 Vibe Coding

Vibe Coding 为助手增加了什么？

它增加了一套工程指令：入口技能、领域技能和具体工作流，涵盖产品行为、API、数据、安全、基础设施、AI 功能、MCP、Web 渲染和发布检查。它不会添加执行引擎或模型。

它与单条提示词有什么区别？

技能先选择领域和操作，工作流再定义目标、约束、工程不变量和验证方法。共享流程明确区分检查、实现和验证。

插件会运行服务或收集数据吗？

它不会安装 MCP 服务器、后台服务、账户连接或遥测。助手使用现有工具和权限。网站不使用分析工具或第三方脚本；浏览器本地存储仅用于记住目录偏好。

可以与 Claude 一起使用吗？

本版本包含 Claude Code 插件清单和公开插件市场。技能通过 /vibe-coding:技能名 调用。文档中的安装方式面向 Claude Code 仓库开发；其他 Claude 界面是否可用取决于其插件支持。

支持哪些语言？

目录、搜索标签和可复制提示词支持英语、西班牙语、俄语和简体中文。技术指令仍使用英语。可以要求助手用你偏好的语言回答。

它能保证代码正确吗？

不能。结果取决于模型、上下文、工具和检查条件。工作流要求提供证据，并区分实际观察、假设和受阻的检查。使用前请审阅修改。

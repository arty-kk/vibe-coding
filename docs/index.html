A workflow that follows your intent

Each skill routes to focused instructions. The assistant follows the relevant code, identifies the contract owner and checks the affected behavior. Detailed recipes load when needed.

Inspect

Ask for an audit or review to get evidence, impact and a concrete next step. Product code stays unchanged.

Implement

Ask for a fix or improvement to authorize the relevant change, including affected callers and contracts.

Verify

Check the requested behavior and see what passed, failed or could not be tested. A bounded check does not certify the whole project.

Start with a real engineering task

Map a repository ↗

Trace the API, data owners and runtime flow before working in an unfamiliar codebase.

Review a patch ↗

Inspect the full change and its direct dependencies for actionable defects.

Debug one failure ↗

Follow a reproducible bug to its owner, fix the cause and run a meaningful check.

Check a release ↗

Compare release evidence with required gates and report the remaining gaps.

Install the plugin

The same 46 skills work in both hosts. Choose the assistant you use for repository work.

Codex

Install Vibe Coding from the OpenAI Plugins Directory, then start a new task.

Open in the Codex directory ↗

$vibe Map this repository and explain its main contracts.

Claude Code

Add this public GitHub marketplace and install the plugin in Claude Code:

claude plugin marketplace add arty-kk/vibe-coding
claude plugin install vibe-coding@vibe-coding

Start a new Claude Code session, then invoke a skill with its plugin namespace:

/vibe-coding:vibe Map this repository and explain its main contracts.

Installation and update guide ↗

The plugin is free under the MIT license. Codex and Claude access, model usage and your project’s services follow their own pricing and requirements.

About Vibe Coding

What does Vibe Coding add to my assistant?

It adds engineering instructions: an entry skill, domain skills and focused recipes. These cover product behavior, APIs, data, security, infrastructure, AI features, MCP, web rendering and release checks. It does not add an execution engine or a model.

How is this different from a single prompt?

A skill first selects the relevant domain and operation. A recipe then defines the goal, constraints, engineering invariants and verification method. The shared workflow separates inspection, implementation and checks.

Does the plugin run services or collect data?

It installs no MCP server, background service, account connection or telemetry. Your assistant uses its existing tools and permissions. The website uses no analytics or third-party scripts; local browser storage remembers catalog preferences.

Can I use it with Claude?

This release includes the Claude Code plugin manifest and a public marketplace. Its skills are invoked as /vibe-coding:skill-name. The documented setup is for Claude Code repository work; availability in other Claude surfaces depends on their plugin support.

Which languages are supported?

The catalog, search labels and copyable prompts support English, Spanish, Russian and Simplified Chinese. Technical instructions remain in English. Ask the assistant to respond in your preferred language.

Does it guarantee correct code?

No. Results depend on the model, available context, tools and checks. The workflows require evidence and distinguish observed results from assumptions and blocked checks. Review changes before relying on them.
